# KodeGPT v0.1 Detailed Execution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement KodeGPT v0.1 as the independent ChatGPT-first, MCP-native local-development platform defined by the 2026-08-09 Master Blueprint, while keeping Rust as final OS authority and preserving Pranikah/CodexPro isolation.

**Architecture:** TypeScript owns MCP/auth/application semantics and maps public `ws_...`/`op_...` identities to private kernel capabilities. A persistent concurrent Rust kernel owns trusted-root identity, root-FD workspace authority, `openat2` filesystem access, Bubblewrap process isolation, raw output spooling, protected-state enforcement, and durable security audit. TypeScript and Rust communicate only through exact `Content-Length` framed JSON-RPC 2.0 over persistent stdin/stdout.

**Tech Stack:** Node.js >=24, pnpm 10.15.0, TypeScript 5.9.2, Vitest 3.2.4, Zod 4.3.6, Rust stable, Bubblewrap >=0.11.2, MCP `2026-07-28`, `@modelcontextprotocol/server` 2.0.0, `@modelcontextprotocol/core` 2.0.0, `@modelcontextprotocol/node` 2.0.0-beta.5, `@modelcontextprotocol/client` 2.0.0-beta.5 for dev/test, `@modelcontextprotocol/ext-apps` 1.7.5 only in the browser View/build layer, esbuild 0.28.1.

## Global Constraints

1. Product display name is `KodeGPT`; CLI name is `kodegpt`.
2. Repository root is `/home/sauron/dev/kodegpt`; product state root is `~/.kodegpt`.
3. Pranikah and CodexPro are external. No KodeGPT runtime dependency, state/token reuse, security fallback, or mutation is permitted.
4. MCP target is exactly `2026-07-28`; no legacy initialize/session/SSE compatibility path may become the v0.1 core.
5. HTTP is loopback by default and requires size/media-type, Host, Origin, then bearer validation before MCP dispatch.
6. MCP cannot establish workspace trust. Trust is local-only.
7. Persistent workspace trust stores canonical display root + device major/minor + inode; mount IDs are runtime-only.
8. Current mount topology must be parsed at workspace registration and failure is fail-closed on Linux x86_64.
9. All workspace filesystem operations are authorized by Rust using a retained root directory FD.
10. Security-sensitive path resolution uses `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV`.
11. Project-local policy only narrows the trusted/global ceiling.
12. Public tools operate only on READY workspaces.
13. Runtime stdout is framed protocol only; no production `println!`/`print!` diagnostics.
14. Public process execution is `(logicalExecutable, argv[])`; never implicit `/bin/sh -c`.
15. Workspace PATH never selects the executable; trusted executable identity is root-owned/safe-mode and device+inode+mode revalidated immediately before spawn.
16. Bubblewrap is a required boundary; reference floor is `>=0.11.2` and functional probes are mandatory.
17. Child workspace path is always `/workspace`, bound from the retained root FD; never re-resolve the host root pathname for sandbox binding.
18. Effective `allowWrite` determines writable/read-only child mount; Git is always read-only.
19. `inherit_env=false`; construct child environment from empty.
20. `network=localhost` and `network=allowlist` are unavailable in v0.1 and fail closed.
21. Audit decision persistence happens before every workspace OS action; audit failure blocks the action and later OS work fails closed after outcome persistence failure.
22. Raw output spool exists before Git/process and spools before inline truncation.
23. Public artifact identity is opaque; no raw host path leaves Rust.
24. External extension manifests are declarative JSON-only; external code/HTML/commands do not execute.
25. Durable stores use `schemaVersion: 1` and reject unknown future versions.
26. Tool annotations are exact client hints; Rust policy remains authoritative.
27. MCP Apps is progressive enhancement and server registration remains on `@modelcontextprotocol/server` v2.
28. KodeGPT server source must not import `@modelcontextprotocol/sdk` v1 or `@modelcontextprotocol/ext-apps/server`.
29. Deterministic CI does not depend on ChatGPT. Host compatibility is a separate manual gate.
30. Every security bug gains a permanent regression test.
31. No task is complete while its required verification command fails.
32. Never weaken a locked security boundary to bypass a failing host prerequisite.

# Review-Gate Protocol

Every named gate uses this exact reviewer sequence:

1. Read the tracker and identify the commits since the previous gate.
2. Run the gate's required commands fresh.
3. Review the changed-file diff, not only test summaries.
4. Map every changed security-sensitive path to one or more regression tests.
5. Search for forbidden fallback patterns introduced during the batch.
6. Verify no external Pranikah/CodexPro state was made a runtime dependency.
7. Record `PASS` or `REJECT` with evidence in the tracker.
8. Only after PASS may the next batch begin.

A reviewer rejection is expected to result in a small corrective RED/GREEN cycle inside the same batch, not a silent change to the locked architecture.
