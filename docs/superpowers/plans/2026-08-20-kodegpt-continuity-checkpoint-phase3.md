# KodeGPT Continuity Checkpoint Phase 3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans and superpowers:test-driven-development task-by-task.

**Goal:** Persist one bounded conflict-resistant development checkpoint per trusted workspace and expose it through existing `workspace.info` plus exactly one mutation tool, `workspace.checkpoint`.

**Architecture:** Keep checkpoint data in KodeGPT private state keyed by durable `trustId`. `WorkspaceManager` owns checkpoint read/mutation lifecycle because it already owns READY workspace↔trust binding, untrust lifecycle, and private Rust audit calls. The store uses schema-v1 JSON, atomic replacement, private permissions, and ephemeral per-trust in-process serialization solely to make compare-and-swap atomic for concurrent requests; there is no persisted lock, queue, scheduler, conversation database, or task runtime.

**Tech Stack:** TypeScript 5.9, Node filesystem primitives, Vitest, existing `WorkspaceManager`, Rust runtime/protocol audit sink, MCP server/Zod schemas.

**Spec:** `docs/superpowers/specs/2026-08-20-kodegpt-developer-environment-continuity-design.md` Part F / Phase 3.

## Global Constraints

- Persist at most one checkpoint per durable workspace trust entry at `workspace-checkpoints/<trustId>.json`.
- Checkpoint is development state only; never persist conversations, chain-of-thought, complete stdout/stderr, source files/diffs, PR/CI databases, scheduler state, or autonomous retries.
- Persisted schema version is exactly `1`; future versions fail closed.
- Caller-controlled body contains only `objective`, `status`, `baseline`, `nextActions`, `evidenceRefs`, `blocker`, `notes`.
- `revision` and `updatedAt` are generated by KodeGPT and never caller-controlled.
- `objective` <= 2 KiB UTF-8.
- `nextActions` <= 8, each <= 512 UTF-8 bytes.
- `evidenceRefs` <= 16; `ref` <= 512 bytes, optional `summary` <= 1 KiB.
- `blocker` <= 2 KiB; `notes` <= 4 KiB.
- Total serialized checkpoint <= 16 KiB UTF-8.
- `baseline.headOid`, when present, is exactly 40 or 64 lowercase/uppercase hexadecimal characters and is persisted as supplied normalized lowercase.
- `blocked` requires non-empty `blocker`; `active` forbids `blocker`; `complete` forbids `blocker` and requires `nextActions:[]`.
- Create: `upsert` without `expectedRevision`; existing checkpoint => `CHECKPOINT_STALE`.
- Update: `upsert` with exact current `expectedRevision`; missing => `CHECKPOINT_NOT_FOUND`; mismatch => `CHECKPOINT_STALE`.
- Clear requires exact current `expectedRevision`; missing => `CHECKPOINT_NOT_FOUND`; mismatch => `CHECKPOINT_STALE`.
- No dedicated read tool: `workspace.info` gains optional `checkpoint`.
- Add exactly one public tool `workspace.checkpoint`; Phase 3 bumps semantic surface `0.16 -> 0.17` and public tools `75 -> 76`.
- External MCP protocol remains `2026-07-28`; runtime product version remains `0.1`.
- Checkpoint mutation audit uses the single Rust durable audit sink with decision/success/failed ordering.
- Untrust removes checkpoint state as part of the local untrust lifecycle; stale checkpoint data must never remain accessible through an untrusted workspace.

### Task 1 — Bounded checkpoint store and atomic CAS

**Files:**
- Create: `packages/core/src/workspace-checkpoint-store.ts`
- Create: `packages/core/src/workspace-checkpoint-store.test.ts`
- Modify: `packages/core/src/index.ts`

**Interfaces:**

```ts
export type WorkspaceCheckpointStatus = "active" | "blocked" | "complete";
export type WorkspaceCheckpointEvidenceKind =
  | "artifact" | "process" | "preview" | "pr" | "ci" | "git" | "note";

export interface WorkspaceCheckpointBody {
  objective?: string;
  status: WorkspaceCheckpointStatus;
  baseline?: { branch?: string; headOid?: string };
  nextActions: string[];
  evidenceRefs: Array<{
    kind: WorkspaceCheckpointEvidenceKind;
    ref: string;
    summary?: string;
  }>;
  blocker?: string;
  notes?: string;
}

export interface WorkspaceCheckpoint extends WorkspaceCheckpointBody {
  schemaVersion: 1;
  revision: number;
  updatedAt: string;
}

export class WorkspaceCheckpointStore {
  read(trustId: string): Promise<WorkspaceCheckpoint | undefined>;
  upsert(input: {
    trustId: string;
    body: WorkspaceCheckpointBody;
    expectedRevision?: number;
  }): Promise<WorkspaceCheckpoint>;
  clear(trustId: string, expectedRevision: number): Promise<void>;
  purge(trustId: string): Promise<void>;
}
```

- [ ] Write RED tests for create revision 1, exact update revision increment, stale create/update, missing update, clear CAS, future schema rejection, malformed/unknown fields, every field/count/byte bound, status invariants, head OID validation, private 0600 file + 0700 directory, total 16 KiB bound, and server clock generation.
- [ ] Add a RED concurrent-writer test: two updates with the same `expectedRevision` start concurrently; exactly one succeeds and the other returns `CHECKPOINT_STALE`.
- [ ] Implement strict parser/validator, atomic temp-file replacement, canonical `trust_<32hex>` filename validation, immutable clones, and injected clock for tests.
- [ ] Implement ephemeral keyed promise serialization around `upsert/clear/purge`; remove idle keys after each mutation so no persistent queue/state remains.
- [ ] Run core store tests + core typecheck GREEN.
